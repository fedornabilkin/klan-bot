# Klan Bot

Самостоятельный Telegram worker: получает обновления через `getUpdates` и передаёт их Klan API по HTTP. База данных и исходники соседних приложений ему не нужны.

## Структура

| Каталог | Содержимое |
| --- | --- |
| `Project/` | Код, npm-пакет, TypeScript, `.env`, зависимости и сборка |
| `Docker/` | Dockerfile, Compose и пример окружения контейнера |
| `Deploy/` | Конфигурация systemd |
| `Scripts/` | Подготовка настроек и локальный запуск |
| `Docs/` | Протокол и развёртывание |
| `Agreements/` | Соглашения разработки |

## Локальный запуск без Docker

Нужны Node.js 22.12+ и npm. Из корня репозитория:

```sh
node Scripts/prepare-local.mjs
cd Project
npm ci
```

В `Project/.env` укажите `TELEGRAM_BOT_TOKEN`, адрес API в `BOT_BACKEND_URL` и общий секрет в `BOT_BACKEND_SECRET`. Секрет должен совпадать с `BOT_INTERNAL_SECRET` у API. Имя бот получает через Telegram при запуске. Подготовка создаёт файл из примера, если его ещё нет, и сохраняет существующие настройки.

```sh
npm run check:config
npm run dev
```

Проверка конфигурации не обращается к Telegram. `npm run dev` запускает бота с перезапуском при изменении кода. Для обычного запуска из `Project/`:

```sh
npm run build
npm start
```

На Windows можно открыть `Scripts/start-local.cmd`: он подготовит `.env`, при необходимости установит зависимости, проверит конфигурацию, соберёт приложение и запустит его в текущем окне. Остановка — Ctrl+C. Подтверждённая позиция Telegram хранится в `Project/.local/offset.json` и сохраняется между запусками.

После обновления старой структуры сначала остановите бота и выполните подготовку настроек. Исходные приватные файлы сохраняются; проверьте новый путь offset перед повторным запуском. После проверки старые копии можно убрать вручную. На один Telegram-токен должен работать только один worker.

## Проверки

Из `Project/`: `npm test`, `npm run typecheck`, `npm run build`. Тесты используют подставной транспорт и временные файлы; реальный Telegram и база не нужны.

На общем VPS выполните `sudo bash setup-server.sh`. Скрипт подготовит каталоги и хранилища трёх компонентов для пользователя `deploy`. Для отдельного сервера бота добавьте аргумент `bot`. [Скрипт](Deploy/setup-server.sh) · [Подготовка VPS без домена](Docs/deployment-github-vps.md)

Другие инструкции: [локальное развёртывание и systemd](Docs/deployment.md), [протокол](Docs/protocol.md), [соглашения](Agreements/CONVENTIONS.md).
