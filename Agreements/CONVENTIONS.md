# Соглашения Klan Bot

## Структура и независимость

- Код, npm-пакет, конфигурация TypeScript, зависимости и сборка находятся в `Project/`. Команды npm выполняются из `Project/`.
- Dockerfile, Compose и контейнерные параметры находятся в `Docker/`; конфигурации серверных служб — в `Deploy/`; сценарии локального запуска — в `Scripts/`; документация — в `Docs/`; соглашения — в `Agreements/`.
- В корне остаются README, AGENTS и необходимые Git-файлы. Не возвращайте npm-пакет, исходники или файлы развёртывания в корень.
- Репозиторий самодостаточен: не импортируйте исходники и конфигурацию из соседних репозиториев. Docker build context — корень этого репозитория; используйте `Docker/Dockerfile` и его собственный ignore-файл.
- Локальная разработка и запуск должны работать через Node.js без Docker.

## Работа бота

- Worker отвечает за доставку обновлений. Проверки членства, доступа, профили и сессии принадлежат API.
- Не выводите токен, Authorization header, полный URL Telegram, тело сообщения и исходные исключения HTTP-клиента в журнал.
- Offset сохраняется только после подтверждения API. Ошибка обработки или записи offset не означает успех; повторите доставку.
- Запускайте только один worker на один Telegram token. Обработка должна переживать повторную доставку.
- Для shutdown используйте AbortSignal, освобождайте таймеры и сетевые запросы.
- Реальные сообщения и изменения в Telegram допустимы только по явному запросу пользователя.

## Настройки и проверки

- Реальные секреты, offset, журналы и временные результаты не коммитьте. Локальная конфигурация — `Project/.env`, локальное состояние — игнорируемый `Project/.local/` либо внешний постоянный каталог. В контейнере используйте volume.
- `.env.example` содержит только пустые значения и безопасные примеры. `Scripts/prepare-local.mjs` не должен перезаписывать существующие настройки и состояния.
- Проверяйте изменения из `Project/`: `npm test`, `npm run typecheck`, `npm run build`. Проверка `npm run check:config` не должна обращаться к сети.
- Следуйте [протоколу](../Docs/protocol.md) и [инструкции развёртывания](../Docs/deployment.md).

## Коммиты

- Фиксируйте завершённые логические изменения коммитами после относящихся к ним проверок.
- Сообщения коммитов — заголовок и подробное описание — обязательно пишите на русском языке.
- Названия технологий, идентификаторы и пути файлов оставляйте в исходном написании, если это нужно для точности.

## Синхронизация облачной и локальной работы

- Изменения, подготовленные в облаке, сначала переносите в соответствующий локальный репозиторий пользователя. Сохраняйте историю, незакоммиченные изменения, приватные настройки и данные.
- После проверки локальной копии отправляйте коммиты в GitHub из неё, когда публикация разрешена пользователем и доступна. Не публикуйте напрямую из облачной копии, если пользователь явно не задал другой порядок.
- Если локальная среда недоступна или перенос заблокирован, сохраните подготовленные коммиты для последующего переноса и явно сообщите, что локальная синхронизация и публикация ещё не завершены.
